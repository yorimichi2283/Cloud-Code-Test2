# Telop Shifter

Premiere Pro用のUXPパネルプラグインです。タイムライン上で選択したテロップ（テキスト/グラフィック/MOGRTクリップ）の
位置（X, Y座標）とスケールを、まとめてリアルタイムに調整できます。

## できること

- 「対象」でトラックを選ぶか（各トラックのクリップ数も表示されるので、テロップのあるトラックが
  分かりやすい）、「タイムラインで選択中のクリップ」を選んで、Premiereのタイムラインでドラッグ選択した
  複数のテロップクリップを対象にできる
- 「テロップ（グラフィック）だけを対象にする」にチェックを入れておくと、同じトラックに動画クリップが
  混ざっていても動画は動かさない（動画クリップは「モーション」しか持たないのに対し、テロップは
  「ベクトルモーション」などの専用の変形を持つ、という違いで判定）
- パネルの「読み込む」を押すと、対象クリップの現在の位置・スケールを記録
- X座標・Y座標・スケールそれぞれ、◀▶の矢印ボタン（1クリック=5、Shift+クリック=1、押しっぱなしで
  連続移動）、または数値を直接入力して調整できる
- 矢印ボタン・数値入力のいずれでも、選択した全クリップにまとめて、その場でリアルタイムに反映
- 「横位置を全クリップでそろえる」で、読み込んだ全クリップの横位置を1つの値に統一できる
  - 使い方: まずX座標の矢印で**見た目が中央に来るように合わせ**、そのあとボタンを押すと、
    全クリップがその横位置に揃う
  - 基準値は「読み込んだクリップの横位置の中央値 ＋ 現在の調整分」。実際のクリップから取った値なので、
    画面外に飛ぶことがなく、1件だけズレているクリップを多数派に合わせる用途にも使える
  - 縦方向の調整はそのまま保持される。揃えた後はその位置が新しい基準になり、X座標の値は0に戻る
  - 注意: 計算でフレーム中央を求める方式は採用していません。Premiereの拡張API（UXP）にはテキストの
    幅や位置（バウンディングボックス）を取得する手段がなく、さらに保存されている位置の値の意味が
    テンプレートによって異なるため、固定値（0やアンカーポイント）を書き込むとテロップが左端や右端へ
    飛んでしまうことが実機テストで判明したためです
- 誤操作で極端な値に飛ばないよう、X/Y座標は映像フレームの縦横幅の範囲内、スケールは-95%〜+300%の範囲に
  自動的に収まる
- 「リセット」で読み込んだ時点の位置に一括で戻せる
- 通常のテキストクリップの「モーション」エフェクトの位置/スケールと、Premiereのグラフィッククリップが
  持つ「ベクトルモーション」やMOGRT（Essential Graphics）側で公開されている位置/スケール系パラメータの
  両方に対応（パラメータ名に "Position/位置" "Scale/スケール" を含むものを自動検出）。1つのクリップに
  両方が乗っている場合は、二重に動いてしまわないよう内容側（ベクトルモーション/MOGRT側）だけを調整し、
  クリップ全体の基本の「モーション」はそのまま残す。クリップ一覧の `[エフェクト名]` 表示と、下のログ欄で
  実際にどのエフェクトが調整対象に選ばれたかを確認できる

## 制限事項

- すでにキーフレームが打たれている位置/スケールパラメータは、意図しない上書きを避けるため対象外にしています
  （読み込み時のクリップ一覧に「キーフレーム済みのため対象外」と表示されます）
- パラメータの検出は表示名（英語 "Position"/"Scale"、日本語 "位置"/"スケール"）に基づく簡易マッチングです。
  Premiereの表示言語によっては見つからない場合があります
- 調整中はPremiereへの書き込みが（150msごとに間引いてはいますが）複数回発生するため、Undo履歴が
  複数に分かれます。一連の調整全体を取り消したい場合は「リセット」ボタンの利用を推奨します
- パネルにキーボードフォーカスがある状態だと、Cmd+Z / Ctrl+ZがPremiere本体に届きません。Undoしたい
  場合は、一度タイムラインをクリックしてからショートカットを押してください

## セットアップ（UXP Developer Toolでの読み込み）

1. Premiere Pro 25.2以降がインストールされていること
2. [UXP Developer Tool](https://developer.adobe.com/creative-cloud/uxp/) をインストール
3. UXP Developer Toolで「Add Plugin」からこのリポジトリの `manifest.json` を選択して読み込み
4. Premiere Proでプロジェクトを開いた状態で、UXP Developer Tool上の「Load」を押す
5. Premiere Proのウィンドウメニューからパネル「Telop Shifter」を表示

## 使い方

1. 「対象」で、調整したいトラック（例: `V3`）を選ぶ。もしくはPremiereのタイムラインで対象クリップを
   ドラッグ（またはShift+クリック）で複数選択し、「タイムラインで選択中のクリップ」のままにする
2. パネルの「読み込む」ボタンを押す
3. 読み込んだクリップの一覧と、検出できた位置/スケールパラメータの数が表示される
4. X座標・Y座標・スケールの◀▶ボタンを押す（押しっぱなしで連続移動）、または数値欄に直接入力する
5. どの操作も、選択した全クリップの位置とサイズにまとめてリアルタイムに反映される
6. 横位置を揃えたい場合は、X座標の矢印で見た目を合わせてから「横位置を全クリップでそろえる」を押す
7. 元に戻したい場合は「リセット」ボタンを押す（中央揃えした後でも、読み込んだ時点の位置に戻ります）

## ファイル構成

- `manifest.json` — UXPプラグインのマニフェスト
- `index.html` / `styles.css` — パネルのUI
- `index.js` — Premiere Pro UXP Scripting API (`require("premierepro")`) を使ったロジック本体
- `icons/` — パネル・プラグイン一覧用のアイコン（仮のプレースホルダー。差し替え可）

## 技術メモ

このプラグインは Adobe公式の `@adobe/premierepro` 型定義とサンプルリポジトリ
(`AdobeDocs/uxp-premiere-pro-samples`) のAPI仕様に基づいて実装しています。実機のPremiere Proでの
動作確認はこの開発環境では行えないため、UXP Developer Toolで読み込んでの実機テストをお願いします。

## これまでに修正した不具合（実機テストで発見）

- スライダーがクリック位置に一気に飛んでしまう → 数値入力＋ラベルドラッグ方式に変更
- ＋/−ボタンを押しっぱなしにすると値が暴走する → Pointer Captureで確実に停止するよう修正
- グラフィッククリップの「ベクトルモーション」と「モーション」を同時に二重に動かしてしまう →
  内容側のエフェクト（ベクトルモーション）だけを1つ選んで調整するよう修正
- ラベルドラッグの感度が「移動幅」設定に連動し、大きい移動幅だと少し触れただけで極端な値に飛ぶ →
  ラベルドラッグは常に1px=1単位に固定
- 対象トラックのドロップダウンで選んだ番号と、実際に変更されるトラックがズレる（例: V4を選んだのに
  V2が変わる） → Premiere内部のトラック番号（先頭が最上段）と画面表示（V1が最下段）の向きが逆だった
  ため、変換処理を修正
- 「ベクトルモーション」の位置の値が反映されない → 内部的な値の形式（配列形式）を読み違えていたため、
  どちらの形式でも読み取れるよう修正
- 診断ログ自体が実際の値を正しく表示できていなかった → 修正
- 過去のバグで壊れた値（16bit整数の上限ちょうどの32767など）が乗ったクリップに、さらに少し足すと
  また壊れた値になる → 元の値が異常な範囲だった場合は0（スケールは100）として扱い直す、かつ書き込む
  直前の最終値にも上限・下限をかけて防止
- 大きい丸いつまみのスライダーが分かりにくい → Premiereのエフェクトコントロール風の、小さな◀▶矢印
  ボタン（押しっぱなしで連続移動）に変更
- **位置がピクセル単位で扱えていなかった（最大の原因）** → Premiereの位置の値は内部的に「ピクセル」
  ではなく「フレームに対する比率」で保持されている（1080x1920のシーケンスで中央＝`0.5, 0.5`、
  エフェクトコントロールの表示は`540.0, 960.0`）。そこにピクセル値をそのまま足していたため、
  「1」動かすつもりが実際には「フレーム1枚分」動いていた。これが「すぐ消える」「変な位置に飛ぶ」
  「32767になる」の共通の原因。フレームサイズで割ってから加算するよう修正
- 対象トラックの番号がまだズレる（V2を選んだのにV1が読み込まれる） → APIのインデックスと画面表示の
  対応を推測するのをやめ、各トラックが持つ実際の名前（Premiereが表示している`V1`,`V2`…）を読んで
  ドロップダウンを作るよう変更
- 矢印ボタンが反応しない → UXPパネル内では`setPointerCapture`が例外を投げることがあり、その場合に
  後続の「値を動かす処理」ごと中断されていた。try/catchで囲み、さらにクリックのフォールバック処理も
  追加。あわせて1クリック=1pxでは見た目で分からないため、1クリック=5（Shiftで1）に変更
- Cmd+Zが反応しない → 書き込みのたびにUndo履歴が1件ずつ積まれ、1px分しか戻らないため反応していない
  ように見えていた。書き込みを150msごとに間引いて履歴の件数を削減（フォーカスの問題は上記「制限事項」
  を参照）
- トラックを選ぶと、テロップではなく動画クリップが動いてしまう → 「テロップだけを対象にする」
  チェック（既定でON）を追加し、動画クリップは読み込み対象から除外。どのトラックを実際に読んだか、
  各トラックのクリップ数もログとドロップダウンに表示するよう変更
- 「中央揃え」でテロップが左端（`0`を書き込んだ場合）や右端（アンカーポイントの値を書き込んだ場合）に
  飛ぶ → 保存されている位置の値の意味がテンプレートによって異なり、固定値の計算では正しい中央を
  求められないと判明（APIで文字の幅も測れない）。**実際のクリップの位置の中央値＋現在の調整分**を
  基準にする方式に変更し、「矢印で見た目を合わせてからボタンで全クリップに適用する」操作に改めた
- パネルを縦長にしないと下まで表示されない → パネル内をスクロール可能にし、項目を1行にまとめて
  コンパクト化。セクションごとに見出しと仕切り線を追加し、最小サイズも220x180まで縮小
